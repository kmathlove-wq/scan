## 1. 한 줄 요약

폰이나 컴퓨터 브라우저에서 종이(문서)를 카메라로 찍으면, 프로그램이 **종이의 네 모서리를
자동으로 찾아** 배경을 잘라내고 **반듯하게 편다**. 사용자가 모서리를 손으로 고칠 수 있고,
필터(원본/자동보정/흑백/회색)를 고른 뒤 **이미지(PNG·JPG) 또는 PDF로 저장**한다.

- 서버 없음. 사진은 전부 사용자 기기 안에서만 처리되고 외부로 전송되지 않는다.
- AI API 키 불필요. 종이 인식은 컴퓨터 비전(OpenCV) 계산으로 한다.
- 설치 없음. 웹페이지 하나(`index.html`)로 동작.

## 2. 사용하는 외부 도구 (무료, CDN에서 불러옴)

| 도구 | 버전(고정) | 역할 | 불러오는 곳 |
|---|---|---|---|
| OpenCV.js | 4.9.0 | 이미지에서 외곽선·모서리 찾기, 원근 보정, 필터 연산 | `https://docs.opencv.org/4.9.0/opencv.js` (4.10.0은 docs.opencv.org에 미발행 — 구현 중 확인) |
| jscanify | 1.4.0 | OpenCV를 "문서 스캔"용으로 감싼 래퍼 (모서리 검출 + 워프) | `https://cdn.jsdelivr.net/npm/jscanify@1.4.0/src/jscanify.min.js` |
| jsPDF | 2.5.2 | 여러 페이지를 PDF 한 개로 묶기 | `https://cdn.jsdelivr.net/npm/jspdf@2.5.2/dist/jspdf.umd.min.js` |

- 깃허브 페이지는 외부 스크립트 제한(CSP)이 없으므로 위 CDN을 그대로 쓸 수 있다.
- 세 파일 모두 버전을 정확히 고정한다(예고 없는 업데이트로 깨지는 것 방지).
- OpenCV.js는 약 8MB로 크다 → 로딩 중 화면 표시 + 버튼 비활성화로 처리(§7).

## 3. 화면 흐름 (상태 기계)

```
[로딩] → [카메라] ──촬영──▶ [보정] ──담기──▶ [카메라] (반복)
                                     └─다시 찍기─▶ [카메라]
[카메라] ──완료──▶ [정리·내보내기] ──페이지 편집─▶ [보정] ─▶ [정리·내보내기]
```

내부 상태: `screen ∈ {loading, camera, adjust, export}`.

### 3.1 카메라 화면 (`camera`)

- 뒷 카메라 영상을 화면 가득(`<video autoplay playsinline muted>`).
  - `getUserMedia({ video: { facingMode: { ideal: 'environment' }, width: { ideal: 1920 }, height: { ideal: 1080 } } })`
  - `playsinline`은 아이폰 사파리에서 전체화면 강제 재생을 막기 위해 필수.
- 영상 위에 **오버레이 캔버스**: 실시간으로 감지된 종이 사각형을 파란 선으로 그린다.
  - 실시간 검출 루프: 영상 프레임을 가로 640px로 축소한 임시 캔버스에 그리고
    `scanner.findPaperContour()` 실행 → 약 250ms 간격(setInterval).
  - 성능 저하 시 자동으로 간격을 늘리거나(적응형) 사용자가 "테두리 표시 끄기" 토글 가능.
  - 종이를 못 찾으면 오버레이에 안내 문구("종이 전체가 화면에 들어오게 해주세요").
- 하단: 큰 원형 **촬영 버튼**. 좌측 하단: 작은 "사진 파일 고르기" 버튼
  (`<input type="file" accept="image/*">`, 숨김 + 커스텀 버튼).
- 우측 상단: 담긴 페이지 수 뱃지 + "완료" 버튼(1장 이상일 때 활성화).
- 촬영 동작:
  1. 현재 영상 프레임을 **원본 해상도** 캔버스에 그린다 → `sourceCanvas`.
  2. `sourceCanvas`로 `findPaperContour()` + `getCornerPoints()` 실행.
  3. 모서리를 찾았으면 그 좌표, 못 찾았으면 기본 좌표(각 변에서 8% 안쪽)로 `[보정]` 화면 이동.
- 파일 선택 시: 고른 이미지를 `sourceCanvas`에 그린 뒤 같은 2~3단계 수행.

### 3.2 보정 화면 (`adjust`)

- `sourceCanvas`를 화면에 맞게 축소 표시(표시 배율 `displayScale` 기억).
- 그 위에 **모서리 핸들 4개**(SVG 원): 좌상/우상/우하/좌하. 포인터 이벤트로 드래그.
  - 드래그 중 해당 모서리 주변을 확대한 **돋보기**(작은 원형 캔버스)를 핸들 근처에 표시.
  - 핸들 좌표는 항상 `sourceCanvas` 원본 픽셀 기준으로 저장(표시 좌표 ↔ 원본 좌표 변환).
  - 네 점을 이은 사각형 테두리 선도 함께 그린다.
- 버튼: "다시 찍기"(→ camera, 이 캡처 폐기), "이 페이지 담기".
- "이 페이지 담기" 시:
  - 출력 크기 계산: `w = max(|위 변|, |아래 변|)`, `h = max(|왼 변|, |오른 변|)`
    (원본 해상도 최대한 보존). 단, 긴 변이 2000px를 넘으면 2000px로 비율 축소.
  - `scanner.extractPaper(sourceCanvas, w, h, corners)` → `warpedCanvas`.
  - `pages` 배열에 페이지 객체 추가(§4) → `[카메라]`로 복귀.

### 3.3 정리·내보내기 화면 (`export`)

- 담긴 페이지들을 작은 미리보기(썸네일)로 나열.
  - 각 썸네일: 순서 위/아래 이동, 삭제, "다시 보정"(→ adjust, 해당 페이지의 `sourceCanvas`·`corners` 로드).
  - 각 썸네일 아래 필터 선택 버튼 4개: **원본 / 자동보정 / 흑백 / 회색**(§5).
    - 필터 바꾸면 그 페이지의 `filteredCanvas`만 다시 계산(캐시).
- 출력 설정:
  - 페이지 1장: 기본 "이미지". PNG ↔ JPG 토글. (원하면 PDF 선택 가능)
  - 페이지 2장 이상: 기본 "PDF". (원하면 "각 장을 이미지로" 선택 → 아래 참고)
- **다운로드** 버튼:
  - 이미지(1장): `filteredCanvas.toBlob()` → `<a download="스캔.png">` 클릭.
  - 이미지(여러 장): 각 페이지를 순서대로 `스캔-1.jpg`, `스캔-2.jpg` … 로 연속 다운로드
    (브라우저가 여러 다운로드를 물어보면 "허용" 안내 문구 표시).
  - PDF: jsPDF로 페이지마다 이미지 크기에 맞춘 새 쪽 생성(JPEG 품질 0.85) → `스캔.pdf`.
- 하단: "새로 스캔 시작"(pages 비우고 camera로).

## 4. 데이터 모델

```js
page = {
  id: string,              // 고유 id
  sourceDataURL: string,   // 촬영 원본(JPEG dataURL) — 메모리 절약 위해 캔버스 대신 보관
  corners: {               // sourceDataURL 이미지의 원본 픽셀 좌표
    topLeft:     {x, y},
    topRight:    {x, y},
    bottomRight: {x, y},
    bottomLeft:  {x, y},
  },
  warpedCanvas: HTMLCanvasElement,   // 원근 보정 결과(필터 적용 전), 긴 변 ≤ 2000px
  filter: 'original' | 'auto' | 'bw' | 'gray',   // 기본 'auto'
  filteredCanvas: HTMLCanvasElement | null,      // 필터 결과 캐시(필터 바뀌면 무효화)
}

state = {
  screen: 'loading' | 'camera' | 'adjust' | 'export',
  cvReady: boolean,
  liveDetect: boolean,          // 카메라 실시간 테두리 표시 on/off
  stream: MediaStream | null,
  pages: page[],
  draft: { sourceDataURL, corners } | null,   // 보정 중인 캡처(아직 pages에 없음)
  editingPageId: string | null,               // export에서 재보정 중인 페이지
  output: { type: 'image' | 'pdf', imageFormat: 'png' | 'jpg' },
}
```

- 페이지 수 소프트 상한: 20장 넘어가면 "너무 많으면 폰이 느려질 수 있어요" 경고(막지는 않음).
- 원본은 JPEG dataURL로 보관(품질 0.92). 재보정 시 이 이미지를 다시 캔버스로 로드해 워프.

## 5. 필터 (warpedCanvas → filteredCanvas)

모두 OpenCV.js 연산. 입력은 워프된 캔버스, 출력도 캔버스.

| 필터 | 처리 |
|---|---|
| **원본 (original)** | 그대로 복사. |
| **자동보정 (auto)** | ① 그레이스케일 사본을 큰 커널(≈ 이미지폭/8, 홀수)로 흐리게(배경 밝기 추정) → ② `원본 / 배경 * 255`로 나눠 그림자·조명 얼룩 제거 → ③ 각 채널 히스토그램 하위 1%·상위 1% 잘라 대비 스트레치 → ④ 약한 언샤프 마스크(선명화). 컬러 유지. |
| **흑백 (bw)** | 그레이스케일 → `cv.adaptiveThreshold`(GAUSSIAN, THRESH_BINARY, blockSize 15, C 10). 글자 문서에 적합. |
| **회색 (gray)** | `cv.cvtColor(RGBA2GRAY)` 후 다시 RGBA로. |

- 필터 계산은 워프 결과(≤2000px)에서 수행 → 폰에서도 수백 ms 내.
- 모든 `cv.Mat`은 `.delete()`로 즉시 해제(메모리 누수 방지) — 공용 헬퍼 `withMats()`로 감싼다.

## 6. 모듈 구조 (index.html 안의 `<script>`, 하나의 파일 · 논리적 구획)

한 파일이지만 아래 단위로 함수 그룹을 분리하고 주석 헤더로 구분한다.

| 단위 | 책임 | 주요 함수 | 의존 |
|---|---|---|---|
| `cvloader` | OpenCV.js 로드 대기, 준비 이벤트 | `waitForCv()` | OpenCV |
| `camera` | 스트림 시작/정지, 프레임 캡처 | `startCamera()`, `stopCamera()`, `grabFrame()` | 브라우저 |
| `detect` | 종이 검출, 모서리 추출 | `detectCorners(canvas)` | jscanify |
| `livepreview` | 실시간 테두리 루프 | `startLiveLoop()`, `stopLiveLoop()`, `drawQuad()` | detect |
| `adjust` | 핸들 드래그, 돋보기, 좌표 변환 | `mountHandles()`, `getCorners()` | 없음 |
| `warp` | 원근 보정 | `extractPaper(src, corners)` | jscanify |
| `filters` | 4종 필터 | `applyFilter(canvas, name)`, `withMats()` | OpenCV |
| `pagesStore` | pages 배열 CRUD, 상한 경고 | `addPage()`, `removePage()`, `movePage()`, `setFilter()` | 없음 |
| `exporter` | 이미지/PDF 저장 | `downloadImages()`, `downloadPdf()` | jsPDF |
| `ui` | 화면 전환, 렌더 | `show(screen)`, `render()` | 위 전부 |

각 단위는 순수 함수 위주로 만들어, 입력 캔버스/좌표 → 출력 캔버스/좌표로 테스트 가능하게 한다.

## 7. 오류 처리 / 예외 상황

| 상황 | 처리 |
|---|---|
| 카메라 권한 거부 · 미지원 · `getUserMedia` 실패 | 카메라 영역 숨기고 "사진 파일 고르기"를 크게 안내. 앱은 계속 동작. |
| HTTPS 아님(로컬 `file://` 직접 열기) | 카메라 불가 안내 + 파일 선택 모드. (깃허브 페이지는 HTTPS라 정상) |
| OpenCV.js 로딩 지연 | `loading` 화면 + 진행 안내. 로드 완료 전 촬영/파일 버튼 비활성화. 30초 초과 시 새로고침 안내. |
| 종이 검출 실패 | 오류 아님. 기본 사각형으로 보정 화면 진입, 사용자가 수동 조정. |
| 아주 큰 사진(예: 5000×4000) | 검출·워프 전 긴 변 3000px로 축소한 사본 사용(멈춤 방지). 최종 워프 출력은 §3.2 규칙. |
| 모서리가 뒤집힘/꼬임(볼록 사각형 아님) | 담기 직전 검사: 네 점이 볼록 사각형이 아니면 "모서리를 다시 맞춰주세요" 표시, 담기 취소. |
| 메모리 부족(페이지 많음) | 20장 경고. `cv.Mat` 즉시 해제. warpedCanvas 2000px 제한. |
| 필터 연산 예외 | 해당 페이지는 '원본'으로 되돌리고 토스트 안내. |

## 8. 테스트

- **자동(스모크) 1개 — Playwright**: `index.html`을 로컬 서버로 띄우고
  1) OpenCV 준비됨 이벤트 확인, 2) 준비된 종이 사진(fixture)을 파일 입력에 주입,
  3) 보정 화면에서 자동 검출된 네 좌표가 사진 경계 안쪽 합리적 범위인지,
  4) "담기" 후 export에서 warpedCanvas가 비어있지 않고(픽셀 분산 > 임계값) 기대 비율인지,
  5) PDF 다운로드 트리거 시 blob 크기 > 0.
- **필터 순수 함수 테스트**: 단색/그라데이션 캔버스를 넣어 각 필터가 크기 보존 + 예외 없음 확인.
- **수동 체크리스트(README에 기록)**: 아이폰 사파리 / 안드로이드 크롬에서
  카메라 열림 · 실시간 테두리 · 촬영 · 모서리 드래그 · 흑백 필터 · PDF 저장 각각 1회.
